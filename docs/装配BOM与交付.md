# 装配 BOM 与交付（第 331–340 项）

本机版本 0.23.0-local.asmdelivery.1。在 Creo 10.0 中打开实际要统计或交付的顶层装配，并切换至主表示。入口为「BWTL → 插件功能 → 装配 BOM 与交付」。输出在当前 Creo 工作目录的新文件夹内，已有目录受到保护。

| 编号 | 功能 | 输出 |
|---|---|---|
| 331 | 导出分层 BOM | hierarchy.csv，含总装、子装配、父实例、零件路径和状态 |
| 332 | 生成采购分类 BOM | procurement.csv，按自制、外购、标准和待分类统计活动零件 |
| 333 | 比较两版 BOM | bom-diff.csv，列出新增、移除及料号、版本、数量、材料变化 |
| 334 | 检查 BOM 资料完整性 | 默认在聊天显示，可导出 bom-check.csv |
| 335 | 生成紧固件用量表 | fasteners.csv，按规格、长度、安装区域统计 |
| 336 | 生成线束与附件安装表 | wiring.csv，按实例列出线束、扎带、线夹和护套 |
| 337 | 生成维修备件清单 | spares.csv，列出可独立更换的实例、安装位置及同型号总用量 |
| 338 | 生成装配工序卡 | process.csv，按指定顺序记录紧固要求和检查点 |
| 339 | 打包原生装配及依赖文件 | 原生装配、子装配、零件和 native-files.csv |
| 340 | 生成装配交付包 | 原生文件、分层与采购 BOM、图纸 PDF、检查报告 TXT 和交付清单 |

## 资料字段与统计口径

- 331 保留各级实例，标出抑制和不可用状态。采购、紧固件、线束及备件统计使用活动实例。
- 料号、图号、版本、材料和规格优先读取 `PART_CODE`、`DRAWING_NO`、`REVISION`、`MATERIAL`、`SPEC` 等模型参数。Creo 已分配的零件材料也可读取，通用系统材料视为未填写。
- 采购分类使用字符串参数 `BWTL_SOURCE` 的 `MAKE`、`BUY`、`STANDARD`，对应自制件、外购件、标准件。缺失或未知值归入待分类。
- 用量表使用 `BWTL_KIND` 标记 `FASTENER`、`HARNESS`、`TIE`、`CLIP`、`SLEEVE`。紧固件长度来自 `BWTL_LENGTH`。备件使用 `BWTL_SPARE=YES`。
- 安装区域、位置、紧固要求和检查点来自 `BWTL_AREA`、`BWTL_POSITION`、`BWTL_TORQUE`、`BWTL_CHECK`。组件实例参数优先于模型参数，缺项标为「未标注」。工序卡以指定实例顺序为准，支持嵌套路径。
- 333 比较两个不同名的实际装配。零件与子装配优先按模型名配对，其次按两版中唯一的料号配对。同名零件如需比较历史版本，先准备可在同一会话分别加载的不同名模型。

## 原生打包与交付

- 339 从当前装配和 Creo 可读依赖收集已保存的原生文件，保留各文件实际版本后缀，复制前后核对 SHA-256。未载入、未保存、版本不明或不支持的依赖列入 `native-files.csv`。带缺项的输出用于排查。
- 340 先打开并保存选定配置对应的实际装配。把该配置的图纸 PDF 和检查报告 TXT 放在当前工作目录下，并在请求中指定两个文件名。交付清单记录实际装配名及附件来源、校验值。附件内容与装配的业务对应关系由提供文件的人核对。
- 340 要求原生依赖和两个附件齐全才发布交付目录。打包从保存好的文件复制，源模型的保存由用户在 Creo 中完成。

## 验证与回退

使用 `tests/native_assembly_delivery.c` 验证表格内容、缺项、文件复制和失败保护。使用 `tests/native_assembly_delivery_chat.c` 在全新会话从包内加载模型，并通过 BWTL 聊天检查 BOM。另运行回归和隔离检查。

上一版 `0.23.0-local.asmviews.1` 已保留。可通过 BWTL 管理程序在相应安装根目录回退。保存当前 Creo 工作后重开对应会话，聊天和记忆仍使用各自的数据目录。
