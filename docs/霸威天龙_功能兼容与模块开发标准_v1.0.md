# 霸威天龙：功能兼容与模块开发标准

标准编号：BWTL-DEV-001  
标准版本：1.0  
制定日期：2026-10-30  
适用基线：0.21.0-preview.3；Creo Parametric 10.0.0.0。  
状态：开发与发布规范。本文规定的模块开关、工具注册表和自动兼容检查尚未全部实现，文档存在不等于程序已具备这些机制。

## 1. 目的和原则

已验收功能保持原有输入含义和行为。新增能力优先通过新增模块与工具接口接入，避免修改稳定执行路径。任何稳定功能行为变化都必须说明原因、影响、验证和恢复方式。不以“保证绝对不出问题”代替测试。

界面、提示词、调度、读取逻辑和配置也属于变更范围；不能仅因没有修改CAD执行函数就视为无兼容风险。

## 2. 基线与验收状态

基线取当前本机实际文件，源码及DLL指纹见配套《接口冻结基线_0.21.0-preview.3.json》。指纹用于识别变化，不是自动阻止修改的锁，也不代表每个被记录文件都已充分验收。

当前保留的证据：v21原生测试94条操作，87成功、7预期拒绝；安装升级回退22项检查通过。后续紧凑卡片补丁通过隐藏控件检查，灰色配色补丁已编译和官方解锁，没有重新运行完整CAD测试。证据文件位于工程 tests/reports。

稳定范围只包含功能表中明确支持且已核验的范围。待验证项继续保留待验证标记；装配、钣金和工程图等未实现能力不得因本标准而被标成可用。当前新增11—15写入限独立普通单实体零件。

## 3. 旧工具接口冻结

冻结内容包括：工具名称、参数顺序/类型/单位/必填性、枚举含义、允许的目标模型、前置条件、返回数据结构/错误含义，以及是否新建、修改、保存或改变显示目标等副作用。

- 不更名、删除或重新解释旧工具和枚举；不把毫米改成模型单位、不颠倒正负方向，不把当前零件操作改成另建零件。
- 不向旧接口新增必填参数，不让旧合法输入悄悄执行不同操作。
- 新增可选参数也须版本化并验证旧调用；不兼容变化使用新接口名或新的明确协议版本，保留旧接口路由。
- 解析器必须拒绝未知/冲突指令，不将失败命令猜成另一种写操作。
- 历史协议、旧聊天和模型编号不是执行授权；本次工具输入仍须绑定实际模型、参照和版本。
- 旧功能确需修复时允许受控修改：写清缺陷、最小修复、兼容影响和回归结果，不能以“冻结”为由保留已知错误。

当前主要接口定义：model_plan.h、part_command.h、foundation_plan.h、solid_plan.h。AI说明分别包含part_prompt.h、foundation_prompt.h、solid_prompt.h；这些说明也必须与对应接口同步管理。

## 4. 新增功能模块化

新增模块应具有独立模块ID、版本、工具前缀/命名空间、解析器、执行器、提示词片段及相关检查。示例组织为 modules/<模块ID>/，仅为后续目标布局，不表示当前已经迁移完成。

模块描述必须记录：负责人/变更记录、支持的Creo版本与模型类型、工具接口版本、依赖模块及版本、读写权限、预期副作用、前后置检查、错误与恢复策略、测试证据、开关默认值。

稳定业务逻辑不因新增模块被复制成另一套有差异的实现。公共服务只提供必要的读取、事务、错误和日志接口；修改公共服务必须评估所有调用模块。先用适配层接入，避免顺手重构稳定工具。

模块化代码不等于进程隔离。进程内DLL中的崩溃仍可能影响Creo；独立开关也不能隔离内存破坏。当前各功能仍在同一DLL，后续先实现逻辑模块化，是否拆DLL另行评估。

## 5. 独立开关规范（待实现）

目标配置文件：modules.json。每个模块独立 enabled 开关。新模块首次引入默认关闭，测试通过后可在稳定发布配置中明确开启；已经验收且用户正在使用的旧功能默认保持开启。

配置示意，不是当前可生效的配置：

    {"schema_version":1,"modules":{"foundation_v1":{"enabled":true},"standard_solids_v1":{"enabled":true},"experimental_assembly_v1":{"enabled":false}}}

模块ID为规划名称；正式实现时建立注册表并固化映射。

开关必须同时作用于AI可见工具、调度入口和原生执行入口，不能只从界面隐藏。停用工具返回明确“模块已停用”，不替换为其他工具。不允许AI自行开启被用户或配置禁用的模块。

依赖未满足或版本不符时关闭依赖功能并报告原因，不自动改用户配置。配置损坏时：保留备份，禁用实验新增模块；稳定模块仅在兼容配置有效、权限条件满足时可用，否则拒绝写入并提示修复，不能静默开启所有功能。

第一版开关应在启动时读取；运行中切换先停止接收该模块新任务，已有写操作完成或安全中止后再停用，不在事务中途强卸载模块。

## 6. 工具选择与连续任务

使用明确的工具注册表，由当前任务、模型类型和启用模块决定本次工具集合。新增提示词不得覆盖旧工具的单位、目标和权限规则。有限上下文不能成为省略关键校验的理由。

后续自动规划按“读状态—调用一项工具—检查结果—记录进度—继续”执行，不将50条未验证写指令同时提交。重试有次数、耗时及额度上限；失败恢复须使用新读取的状态。改变用户关键设计要求、材料或约束时应询问，不为完成任务偷偷放宽要求。

## 7. 验证与失败处理

每项工具明确可检查的成功条件。仅返回成功码不足以代表建模成功；按工具类型核验目标、特征状态、尺寸/位置、父子参照、实体数量、体积或导出文件等。不能把估算、AI描述或缓存内容作为原生成功证据。

失败优先恢复本次修改，记录恢复结果；无法核实恢复时明确报告并停止后续依赖写操作。重试前检查是否已产生特征，防止重复建模。关闭模块不会撤销已经完成的设计修改。

## 8. 测试与验收

按影响范围选择检查，避免每次小改都运行整套：

| 变更 | 最低检查范围 |
|---|---|
| 颜色、间距、提示文案 | 编译和相关界面/渲染检查；影响模型操作含义的文案另按接口变更处理 |
| 新增独立工具 | 参数校验、相关Creo正反例、关联/结果检查及失败恢复 |
| 共享解析器、状态、事务、提示词路由 | 受影响模块的旧用例回归，必要时完整核心回归 |
| 稳定发行 | 核心兼容回归、安装升级回退、数据保留、模块启停和依赖检查 |

旧任务保留输入、模型模板/前置状态、预期结果、允许误差和失败边界。不能只测新功能。新能力必须标明“已实现”“本机通过”“跨机器通过”等实际状态，不扩大证据范围。

## 9. 发布、版本与回退

稳定版与测试版分开，独立Creo测试会话不触碰用户工作模型；不截图、不接管日常鼠标。用户已授权的关键确认可按限定对象处理，不扩展为日常桌面控制。

VERSION、CHANGELOG、DLL指纹、兼容矩阵、数据格式与发布包对应。已发布安装包不可覆盖，同一版本不可用不同内容重新发布。按需打包，不把每次本地小修都做成完整安装包。

升级保留旧版本DLL、配置和数据备份。回退代码前先检查数据格式兼容；新版写入的数据不一定能被旧代码直接读取。必要时从升级前备份恢复，且不得覆盖或删除用户升级后新增记录而不告知。

新增数据字段或格式必须具备schema版本、迁移检查和备份策略；不让停用模块自动清除该模块历史数据。不得把聊天历史作为待重放任务。

## 10. 每次新增功能的交付记录

逐项填写：功能/模块ID、接口版本、用途、前置条件、输入输出、依赖、默认开关、涉及文件、对旧功能的影响、实际验证、失败恢复、数据迁移、启用步骤、回退方法和已知限制。不能用“测试通过”替代具体测试范围。

验收条件：旧接口兼容；模块可独立停用且原生入口受控；依赖正确；相关成功/拒绝/恢复检查通过；旧核心用例无新增失败；文档与版本一致。尚未实现开关时必须标注未达成，不提前宣布满足此标准。

## 11. 当前实施状态

已具备：版本化DLL、部分独立协议/执行头文件、原生检查及回归记录、安装版本并存和回退。

本次交付：标准文件与当前基线指纹。

尚待实施：统一工具/模块注册表、modules.json读取、执行入口独立开关、依赖检查、自动接口兼容检查。标准文件不会自动加载成运行规则，也不会因为放进数据目录就让AI学会新CAD操作。

本次不修改建模代码、运行开关、聊天记录或已发布安装包。未来实现后更新本节和标准版本，保留旧标准存档。
