# v10 已验证的模板建模修复

已修复的可用流程：读取 Creo 当前 template_solidpart，复制用户空模板，保留默认坐标系、基准面和参数；在副本内建立基础拉伸。独立二维草绘先完成几何、尺寸、求解和重生成，再按 SDK 的 FIRST_FEAT 首个实体流程创建未完成特征、赋入已求解草绘并完成特征，随后重生成、计算体积、显示新零件。

AI 的新建模指令通过 Creo 原生自定义命令队列交回 uiProe2ndImmediate 回调执行，与真实自检的命令上下文一致。无需手动“执行建模”，没有截图、鼠标或键盘模拟。不自动保存零件。

重要限制：当前是基础拉伸，模板的基准面和坐标系保留，但拉伸没有以它们作为父特征；移动基准面不会驱动该拉伸。普通带参照拉伸尚未通过测试，没有发布失败路径，也没有在失败时偷偷改用不同特征。若需要基准面关联，仍需进一步实现。

## 真实 Creo 10 测试

以下六组在隔离 Creo 进程中运行同一后端源代码，全部通过特征完成、重生成和实体体积校验：

1. 80×80×2 mm，中心通孔直径10 mm。
2. 100×200×2 mm，中心通孔直径10 mm。
3. 100×80×2 mm，中心通孔直径10 mm。
4. 外径50、高100 mm圆柱，无孔。
5. 外径50、高100 mm圆柱，中心通孔直径10 mm。
6. 100×80×2 mm板，无孔。

证据在 validation-v10.log；它不是 mock 测试结果。模板本身“材料”关系在自检中曾出现警告，未擅自修改该模板关系。几何重生成和体积校验均成功。

用户手动批准了 CodexHeadlessSelfTest 信任提示，之后自检使用同一已信任插件。测试仅操作独立进程中的测试零件，没有修改用户已有模型。

## 启用

protk.dat 已指向 codex_native_ai_v10.dll，资源继续使用 text-model-v6/text。下次重启 Creo 加载。窗口标题和恢复历史后的提示都标记 v10，避免将旧失败记录误当作新执行结果。当前已运行的 v9 不会热替换。

已编译正式插件；真实测试验证了建模后端，v10 聊天窗口到建模命令的完整收发仍需实际加载后核验。聊天、长期记忆、输入框和回车发送功能保留。旧已失败零件没有删除或保存。

前面曾把 STD_SEC_METHOD=0 判断为无效，后经核对同类 SDK 示例发现该判断过早；不同特征使用不同取值，不将其作为已确认根因。最终修复依据是上述可重复的真实成功测试。
