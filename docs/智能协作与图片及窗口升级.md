# BWTL 智能协作、图片分析与窗口内功能升级

本机版本 `0.23.0-local.workdir.1`，2026-11-06。

在「智能协作」中，可以直接提出「可以帮我做水杯吗」等带有明确对象的建模委托。要做新零件时，即使 Creo 尚未打开模型，也可先新建，再依据实际参照继续加工。若明确把尺寸交给 BWTL 决定，BWTL 会优先采用适用的既有方案或选用合理值。关键信息缺失且未委托时会询问。

验证方法：在独立的空白 Creo 会话，先讨论外径80 mm、高100 mm、壁厚3 mm、底厚5 mm的无把手水杯。选「智能协作」并发送原句「现在可以帮我做水杯了吗？你自己去选择调用功能、自己有想法去做、尺寸你自己给。」核对实际新建的圆柱、内径74 mm、深95 mm的杯腔与单条结果。将同一句放在「只分析」模式时，宿主拦截写入。本次验收日志在 %USERPROFILE%\Documents\BWTL-modeling-language-20261105，安装状态见安装根目录的 modeling-language-update-status.json。需要回退时，先保存并退出 Creo，再用安装管理切回 0.23.0-local.modelintent.1。

模式选择右侧依次为「插件功能」「公司标准」「工作目录」和两个预留键。「插件功能」按现有能力分类。选中一项会把指令填到输入框，必要时切换到适用模式。把每个「待填」标记替换成实际参数后再发送。选错模板可在输入框按 Ctrl+Z 恢复原文字。正在运行的任务可通过菜单里的「停止当前任务」停止。

「插件功能」第一项「功能列表」直接用 Windows 记事本打开当前版本的 `docs\BWTL 功能列表.txt`。验证时点击该项，核对中文标题、分类和版本。新增功能时同步维护清单、菜单和功能表。需要回退时，通过安装管理切换到上一版。

「公司标准」打开 `%LOCALAPPDATA%\BWTL\公司资料`，其中的「公司标准」「技术文件」文件夹可直接放入相应资料。该目录独立于程序版本和聊天数据，目前用作本机文件存放入口。日常更新和回退沿用这个位置。

## 为什么调整

原版每次只处理一条协议，读取参照后即结束，后续建模需要用户再次发送消息；界面同时显示长段几何编号，缺少图片入口。旧对话引擎只负责生成原生协议，不能修改插件源码。本版保留全部已编译CAD工具，通过独立的协作、附件和开发模块扩展交互。

## 窗口中的三种模式

| 模式 | 行为 |
|---|---|
| 智能协作（默认） | 理解目标、简述方案，自动读取参照，执行当前明确的一步，收到真实结果及新快照后继续，完成后总结或针对缺失信息提问 |
| 只分析 | 可讨论需求、比较方案、读取模型和分析图片；宿主拦截新建和模型写入协议 |
| 功能开发 | 直接输入要新增/调整的插件功能，在独立源码副本中编辑、编译和检查；通过后可在同一窗口申请应用 |

“只分析、先讨论、不要执行、帮我分析”等明确讨论措辞也会在本轮启用写入拦截。复杂需求缺少关键尺寸、参照或唯一目标时会询问，不能从图片猜出精确尺寸。模式和意图判断是额外的保守限制，实际操作仍须经过原生协议、模型版本和工作目录检查。

等待补充时会保留原目标和目标模型，用户回复“可以”或简短尺寸可接着原任务；新发出的“只分析/不要执行”等明确限制优先。任务完成后的普通追问不沿用之前的写入授权。

每轮最多 100 步。没有取得新的建模进展时，两次失败即停止。成功完成并校验建模步骤后重新计算该段失败次数，读取参照不会清零。整轮累计最多 4 次失败。 重复同一操作、恢复不确定、活动目标模型改变或请求超时也会停止。新建模型后必须确认其实际成为活动模型，再将后续步骤绑定到该模型。用户点击停止后不再安排后续步骤，已经完成的原生修改保留，默认不自动保存。正在执行的一项原生特征操作按原有原子检查/恢复流程结束。

每次发送默认只有一张答复卡片。运行时发送按钮显示「处理中…」。输入「执行明细」可查看本轮原生回执，最近一轮回执也保存在 `data/last-native-details.txt`。界面支持基础粗体、标题、列表和行内代码。

主窗口保留 BWTL 标题、模式选择、聊天和输入框，以及「读取当前模型」「应用已验升级」「发送给 AI」「停止」「关闭」。Enter 发送，Shift+Enter 换行。验证时检查顶部五个键、菜单指令填入和本机公司资料目录。空附件行应收起。

## 图片

支持“添加图片”、在输入框粘贴截图和拖入图片，可显示缩略图及文件名，每次最多4张。单张输入及归一化后的PNG最多20MB，最大4000万像素、单边不超过16000像素。通过本机WIC验证图片并转换为PNG，原始用户文件不修改；不能解码、超限或缺失的文件会拒绝。

附件副本保存到独立 `data/attachments/`，聊天记录保留对应相对路径。添加附件后才展开预览。输入「清除图片」可清空当前附件，归档副本保留。重启后可重新选择图片继续看图。

用户选定的图片与本轮对话、已有长期记忆及本次模型摘要会发送给本机Codex登录对应的AI。图片中的文字是参考数据，不能作为运行命令、修改权限或升级插件的授权。读图不能代替原生模型、精确工程尺寸或实体几何核验。

图片通过实际安装CLI的 `--image` 参数传入，使用现有本机登录，不复制凭据。依据：[官方CLI图片参数](https://learn.chatgpt.com/docs/developer-commands?surface=cli)、[非交互与结构化输出](https://learn.chatgpt.com/docs/non-interactive-mode)。本机检查的引擎为 `codex-cli 0.164.0`。

## 在窗口里新增功能

Creo 可能继承 PowerShell 7 的模块路径。开发脚本在 Windows PowerShell 5.1 中显式加载随系统安装的 Utility 模块，使文件校验与独立副本准备可以正常运行。

1. 切换“功能开发”，输入具体需求，可同时附图，例如“增加线性孔阵列，保留已有孔和圆角功能”。
2. 后台在 `%LOCALAPPDATA%\BWTL\development\任务ID\source` 创建独立副本，任务状态写入同级日志。窗口可停止任务，结束后显示一张答复卡片。
3. AI通过结构化的读取、写入、逐项兼容审查及完成操作与宿主交互。AI引擎保持只读，只有受限宿主编辑器能写入开发副本；不开放任意终端命令。读取范围为BWTL源码、文档、测试和指定的官方SDK头文件/示例/文档，不读取旧桥接或用户数据。
4. 宿主编译并运行已有回归；基线不能整体重置，涉及冻结文件时必须先读原文件、提交具体改动理由并逐项审查。安装器、隔离模块、开发流程自身和AGENTS不允许由此编辑器修改。编译失败反馈真实日志，最多2轮修复，整个编辑过程最多20轮。
5. 仅界面/文档调整可在编译和回归通过后准备应用。涉及CAD、调度或原生写入的改动，必须提供新增原生测试夹具，并通过独立Creo的核心自检、既有实体/加工回归及新增夹具。未完成原生验收不能升级。Creo首次加载确认可能需要用户核对名称后允许，后台不会操作鼠标。
6. 点击「读取当前模型」右侧的「应用已验升级」，也可发送同名命令。需要原生验收时会先验收，随后在聊天中提示保存模型并正常退出 Creo。退出后后台备份数据、安装新版本并从独立入口启动。安装过程中停止按钮暂时停用。

任务中的 `status.json`、`ui-status.txt`、编辑操作、逐项审查记录、编译/测试日志、源文件及回退副本均保留。失败或取消不会把未验收代码写回真实源目录。应用前再次检查已验收源码、DLL哈希、真实源目录和活动版本，拒绝覆盖期间发生的其他更新。安装后检查聊天、长期记忆和近期上下文哈希，并检查新版实际进程和旧桥接未加载。

本流程提供真实代码开发与升级通道，不能保证任意复杂功能在一次请求内自动完成；缺少可实现接口、必要SDK资料或有效测试时，会保留具体进度和副本，不宣称已经增加功能。需要改变安装、隔离或开发通道本身的维护仍在本机Codex聊天中处理。

## 隔离与数据

继续使用BWTL自己的源码、安装、独立启动配置、数据、日志、备份和Creo进程。开发子进程不连接桌面聊天的工具管道，忽略用户MCP配置，不导出/复制登录凭据，也不调用旧桥接。SDK和本机模板只读复用。

版本目录外的聊天和记忆继续保留，升级仅更新内置功能索引。更新前保存受影响配置、数据和上一版本。源码仍按模块/函数拆分并编译为一个DLL；连续任务和开发流程不会使旧模型能力自动扩展。

## 验证和回退

本机测试资料：`%USERPROFILE%\Documents\BWTL-smart-20261105`。覆盖实际图片识别、WIC归一化/缩略图/文件数量与非法输入拒绝、三模式及忙碌防重发、基础Markdown转义、真实AI连续建模和分析写入拦截、开发副本实际写文件/编译/回归及应用流程。正式部署和运行检查以安装根目录 `smart-update-status.json` 为准，不能以编译代替运行验收。

保存并退出当前BWTL，使用安装管理回退上一版，再从独立入口启动。回退保留当前聊天、长期记忆和图片归档；旧版界面不显示本版的模式和附件入口。已创建的Creo原生特征不会因插件回退而自动删除。不要用旧data覆盖新聊天；源代码回退副本保存在本次更新/开发任务目录。
