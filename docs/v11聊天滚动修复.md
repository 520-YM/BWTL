# v11 聊天滚动修复

已将聊天窗口换成插件进程内的 Windows 原生窗口与 EDIT 控件，无浏览器，无外部桥接程序。Creo 功能区入口和原生建模命令保留，建模后端没有修改。

修复每次重写全文导致聊天区跳到顶部的问题：更新前保存第一可见行和滚动位置，处于底部时更新后用控件消息滚动到底部；用户在翻看旧消息时恢复阅读位置。新发送的指令会重新跟随最新内容。调用只针对本插件拥有的控件，没有键盘输入模拟、鼠标操作、截图或强制设置焦点。

保留聊天记录、记忆、模型读取、自动建模、原生输入框和回车发送。支持 Shift+Enter 换行，输入法组词期间不把回车当成发送。后台AI轮询改用本窗口的一次性 Windows 定时器，关闭窗口停止轮询并取消等待，卸载销毁窗口和注册类。

## 实际控件测试

使用与插件相同的 native_chat_ui.h，在独立测试进程中创建不可见的真实 Windows 原生控件，测试通过：

- 250行聊天首次更新后，第一可见行为227，显示最新内容。
- 继续追加回复仍保持底部。
- 手动程序化滚动本测试控件到首行后，追加消息仍保持首行阅读位置。
- 显式恢复跟随后回到底部。
- 原输入文字和输入焦点未变化。
- Windows 定时器消息能触发后台轮询回调。

这是真实原生控件测试，不是 mock。测试窗口未显示，不涉及用户当前 Creo 窗口。正式 DLL 已使用 Visual Studio 2019 x64 编译成功。Creo 内完整聊天与中文输入法操作仍需加载新版后实际使用验证。

## 生效

protk.dat 已更新为 codex_native_ai_v11.dll，下一次重启 Creo 加载，窗口标题为 v11。不会覆盖当前已加载的 v10；不用更改功能区。资源注册路径和消息文件保留。回退配置为 protk.before-v11.dat，旧 DLL 保留。
